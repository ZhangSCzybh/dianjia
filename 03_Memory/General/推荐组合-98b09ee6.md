# 推荐组合

- `年份 + 年月` 或 `年份 + 月份`：按月计算
- `年份 + 年季 + 年月`：仍按月计算
- 任意时间维度 + `日期`：按日计算

核心原则是：

```text
最终同环比粒度取最细的有效时间维度
```

例如：

```text
年份 + 年月
```

最终粒度是“月”，而不是“年”。

```text
年份 + 年季 + 年月
```

最终粒度仍然是“月”。

```text
年份 + 日期
```

最终粒度是“日”。

## 四、跨维度会导致异常

以下情况容易出现重复、无法匹配或环比错误：

- 周跨月
- 周跨年
- 年份与月份、周次重复组合
- 周次与周次日期范围同时使用
- 选择唯一订单 ID、明细 ID 等明细字段

例如一个周可能跨越两个自然月：

```text
2026-03-30 至 2026-04-05
```

如果同时按“月”和“周”分组，同一周可能被拆到不同月份中，导致同环比口径不一致。

因此：

- 周分析尽量只使用年周
- 月分析尽量只使用年月
- 日分析尽量只使用日期
- 不要混用互相冲突的时间粒度

## 五、同比和环比的基础公式

对于任意指标：

```text
环比 = (本期值 - 上期值) / abs(上期值)

同比 = (本期值 - 同期值) / abs(同期值)
```

如果对比基准为空或为 0：

```text
环比/同比 = NULL
```

不要把分母为 0 的结果强行显示为 0% 或 100%。

## 六、周维度特别注意

周维度需要使用 ISO 周规则：

- 周一是一周第一天
- 周四所在的年份决定该周属于哪一年
- 跨年周不能简单按照自然年份判断
- 本期、上期、同期应保持相同的星期范围

对于非完整周：

```text
本期是周五至周日
上期也应是上一周的周五至周日
同期应是上一年对应 ISO 周的周五至周日
```

不能将部分周与完整周直接比较。

## 七、对现有 SQL 的直接影响

你之前的 SQL 中有：

```sql
yearWeek
```

因此按这张图的规则：

1. 同环比计算粒度应为“周”。
2. 自定义日期只用于限制数据范围。
3. 上期应为本期前移 7 天。
4. 同期应匹配上一年对应 ISO 周。
5. 不能因为筛选控件选择“自定义”就改成按整个自定义区间计算。
6. 如果同时加入 `月份`、`周次` 等无年份字段，可能产生重复记录或错误同比。

可以概括为：

> 列表有时间维度时，列表字段决定同环比粒度；列表没有时间维度时，筛选控件决定粒度。时间字段必须带有足够的年份信息，周跨月、跨年以及非完整周需要单独处理。
