# 会员销售归类异常：品牌 15056

## 一句话结论

销售订单中的品牌会员被归为非会员时，应优先检查会员维表是否错误限制了会员归属店铺。

## 记忆内容

### 问题 / 场景

会员/非会员销售报表与订单客户信息不一致，且异常订单有 `custom_id` 时使用。

### 核心结论

会员归属店铺与销售门店不同不表示客户不是品牌会员；会员维表按当前销售门店过滤会使 LEFT JOIN 失败并误归类。

### 使用方法

对异常订单查询客户在品牌范围内的会员资料，再比较销售门店、会员归属店铺和报表 Join 条件；根据业务定义选择品牌级或本店级会员口径。

## 现象

2026-08-15 至 2026-08-21，重庆万象城店报表显示：

```text
非会员单效单数：2
非会员单效销额：1462.24 元
```

## 定位结果

上一段 SQL 的会员维表限定了当前店铺：

```sql
WHERE brand_id = 15056
  AND storage_id = 1217909137551395841
  AND deleted = 0
```

订单对应的两个 `custom_id` 在品牌会员维表中都存在手机号，但会员资料归属的是其他店铺，因此关联不到当前子查询。

有效非会员金额来自两个订单：

| 订单 | 金额 |
|---|---:|
| 1219234637814167553 | 1043.12 |
| 1219236792760006657 | 419.12 |
| 合计 | 1462.24 |

另有一个 0 元订单，不计入单效单数。

## 解决方案

若业务口径为品牌会员，将会员维表改为品牌范围：

```sql
WHERE brand_id = 15056
  AND deleted = 0
```

去掉当前店铺的 `storage_id` 限制后，两个订单均识别为会员，结果为：

```text
会员单效销额：27875.36 元
非会员单效销额：0 元
```

## 测试结论

需要产品或业务确认“会员”定义。如果是品牌会员，原 SQL 属于 Join 范围错误；如果是本店归属会员，原结果可以成立，但字段应命名为“本店会员/非本店会员”，避免误解。
