## 2. SQL 数据流

1. 从普通销售明细取 `sale_deal_num - sale_refund_num`，排除 `order_type IN (4,5)`。
2. 以门店 + SKU 的首次调拨入、调入、采购入三者最早日期作为首次到店日。
3. 用销售日与首次到店日的日差生成生命周期第 1 至第 26 周及第 26 周后销量。
4. 用期初库存、期间出入库流水计算期间期末库存近似值 `sumPre_num + sumIn_num + sumOut_num`。
5. 合并期间普通销售、储值卡赠品、积分赠品、当前实时库存、近 7 天普通销售和首次到店信息。
6. 通过窗口函数把 SKU 数据汇总为门店 + SKC、门店 + SPU 的库存和销量。
7. 最外层按 SKU 展示字段分组，并用 `count(DISTINCT if(...))` 计算 SKU/SKC/SPU 指标。

## 3. 第 X 周字段口径

### 3.1 首次到店日

对每个门店 + SKU 取以下三个日期的最小值：

```sql
least(
  coalesce(first_alloc_in_date, toDate('2149-06-06')),
  coalesce(first_tran_in_date, toDate('2149-06-06')),
  coalesce(first_purchase_in_date, toDate('2149-06-06'))
)
```

淘汰门店或 `doc_type != 0` 时首次到店日被置为 `NULL`；三个日期都为空时也为 `NULL`。

### 3.2 生命周期日与周

```text
first_day_diff = dateDiff('day', 首次到店日, 销售日) + 1
```

| 字段 | 生命周期日范围 |
| --- | --- |
| 第 1 周 | 1–7 |
| 第 X 周 | `7 × (X-1) + 1` 至 `7 × X`，X=1..26 |
| 第 26 周 | 176–182 |
| 第 26 周后 | 大于等于 183 |

销售日早于首次到店日、首次到店日缺失或等于 `1970-01-01` 时，该销售不会进入任何周字段。周销量只取普通销售净量，不包括积分赠品和储值卡赠品。

## 4. 12 个重点指标映射

| 业务指标 | SQL 别名 | 分子/判定口径 |
| --- | --- | --- |
| 当前铺店 SKC 数 | `storageNowSKCCount` | `countDistinct(skc_id)`，门店 + SKC 下当前 `sum(real_num) > 0` |
| 当前近 7 天动销 SKC 数 | `storageLatest7dSaleSKCCount` | `countDistinct(skc_id)`，门店 + SKC 下近 7 天普通销售净量之和 `> 0` |
| 当前 SKC 动销率 | `storageHasSaleSKCRate` | 近 7 天动销 SKC 数 / 当前铺店 SKC 数；分母为 0 时返回 0 |
| 期间铺店 SKC 数 | `storageQjSKCCount` | 期间期末库存近似值 `> 0` 或期间普通销售净量 `> 0` 的 SKC |
| 期间动销 SKC 数 | `qjHasSaleSKCCount` | 期间普通销售净量 `> 0` 的 SKC |
| 期间 SKC 动销率 | `qjHasSaleSKCRate` | 期间动销 SKC 数 / 期间铺店 SKC 数；分母为 0 时返回 0 |
| 当前铺店 SPU 数 | `storageNowSPUCount` | `countDistinct(spu_id)`，门店 + SPU 下当前 `sum(real_num) > 0` |
| 当前近 7 天动销 SPU 数 | `storageLatest7dSaleSPUCount` | `countDistinct(spu_id)`，门店 + SPU 下近 7 天普通销售净量之和 `> 0` |
| 当前 SPU 动销率 | `storageHasSaleSPURate` | 近 7 天动销 SPU 数 / 当前铺店 SPU 数；分母为 0 时返回 0 |
| 期间铺店 SPU 数 | `storageQjSPUCount` | 期间期末库存近似值 `> 0` 或期间普通销售净量 `> 0` 的 SPU |
| 期间动销 SPU 数 | `qjHasSaleSPUCount` | 期间普通销售净量 `> 0` 的 SPU |
| 期间 SPU 动销率 | `qjHasSaleSPURate` | 期间动销 SPU 数 / 期间铺店 SPU 数；分母为 0 时返回 0 |

注意：字段名中的“铺店”在当前口径实际表示“当前净库存大于 0”，在期间口径实际表示“期间期末库存近似值大于 0，或期间普通销售净量大于 0”，不是严格的“期间内曾经有过库存”。

## 5. SQL 测试点

| ID | 测试点 | 核验方法 | 预期 |
| --- | --- | --- | --- |
| W01 | 第 1 周边界 | 首次到店日当天、第 7 天、第 8 天各放一笔销售 | 当天和第 7 天进第 1 周；第 8 天进第 2 周 |
| W02 | 中间周边界 | 对任意 X 验证第 `7X`、`7X+1` 天 | 分别进入第 X、X+1 周，且不重复 |
| W03 | 第 26 周边界 | 验证第 175、176、182、183 天 | 175 进第 25 周；176、182 进第 26 周；183 进第 26 周后 |
| W04 | 首次到店日缺失 | 三个首次入库日期均为空但存在销售 | 所有周字段均不计该销售，并被异常查询识别 |
| W05 | 销售早于首次到店 | `bill_date < first_in_date` | 所有周字段均不计该销售，并被异常查询识别 |
| W06 | 首次到店日选择 | 三种首次入库日期设置成不同日期 | 使用最早的非空日期 |
| W07 | 周销量守恒 | 汇总第 1–26 周和第 26 周后 | 应等于首次到店日起至结束日的普通销售净量；差额只能来自缺失首次到店日或到店前销售 |
| W08 | 周字段销售来源 | 同日分别造普通销售、积分赠品、储值卡赠品 | 周字段只包含普通销售净量 |
| M01 | 字段映射 | 将原 SQL 12 个别名与产品展示字段逐一比对 | 名称和顺序全部对应，SKC/SPU 不串位 |
| M02 | 当前分子集合 | 找近 7 天有销售但当前库存不大于 0 的 SKC/SPU | 当前 SQL 会计入动销数但不计入铺店数；必须明确是否符合产品口径 |
| M03 | 当前动销率范围 | 在总计行检查当前 SKC/SPU 动销率 | 若业务要求百分比，必须满足 0–1；当前 SQL 存在超过 1 的可能 |
| M04 | 期间分子集合 | 检查期间动销对象是否全部进入期间铺店集合 | 必须成立，因为分母条件显式包含期间普通销售 `> 0` |
| M05 | 分母为 0 | 无库存、无普通销售 | 三种层级动销率都返回 0，不得报除零错误或返回 NaN/NULL |
| M06 | 净销量判定 | 正销 5、退货 5；正销 5、退货 6 | 净量分别为 0、-1，均不算动销 |
| M07 | 排除订单类型 | 混入 `order_type IN (4,5)` | 普通销售、周销量、当前/期间动销均不包含这些记录 |
| M08 | 当前库存口径 | `real_num`、`lock_num`、`transit_num`、`can_use_num` 分别变化 | 铺店判定最终只看汇总后的 `real_num > 0`；其他数量只影响源记录是否被保留 |
| M09 | 近 7 天边界 | 比较 `bill_date >= addDays(today(),-7)` 与 `bill_date >= now()-INTERVAL 7 DAY` | 明确是滚动 168 小时还是含今天的 7 个自然日；不能多算或少算一天 |
| M10 | 期间边界 | 在 2026-07-31、08-01、09-21、09-22 造数 | 期间字段只包含 08-01 至 09-21，两端包含 |
| M11 | 期间库存公式 | 期初、入库、出库分别给定已知值 | `sumPre_num + sumIn_num + sumOut_num` 等于源系统期末库存；重点确认 `out_num` 的符号语义 |
| M12 | 曾铺货但期末为 0 | 期间入库后全部出库且无普通销售 | 当前 SQL 的期间铺店数为 0；若产品定义是“期间曾铺货”，则 SQL 口径不满足 |
| M13 | 赠品动销 | 只有积分赠品或储值卡赠品，无普通销售 | `sumQjTotalSaleNum > 0`，但期间动销数仍为 0；需要业务确认 |
| M14 | SKC 去重 | 同一 SKC 两个 SKU 都有库存/销售 | SKC 铺店数和动销数均只能加 1 |
| M15 | SPU 去重 | 同一 SPU 下两个 SKC 都有库存/销售 | SPU 铺店数和动销数均只能加 1；SKC 数可加 2 |
| M16 | 层级汇总 | 一个 SPU 两个 SKC，仅一个 SKC 动销 | SPU 动销率可能为 100%，SKC 动销率为 50%，这是层级去重的正常结果 |
| M17 | 明细行与总计行 | 同一 SPU/SKC 跨多个 SKU 输出行 | 不允许累加明细行的 SPU/SKC 数；以 `WITH TOTALS` 总计行或独立去重汇总为准 |
| M18 | JOIN 放大 | 检查商品、首到店、淘汰门店维表的业务键唯一性 | 门店 + SKU 在进入窗口函数前最多一行；否则库存和销量会被重复求和 |
| M19 | 固定期间与动态当前 | 隔日重跑原 SQL | 期间仍截止 2026-09-21，但当前库存/近 7 天随 `today()/now()` 改变；历史结果不可直接重现 |
| M20 | `LIMIT` 与总计 | 明细超过 1000 行 | 页面只有前 1000 行；总计行需与不带 LIMIT 的独立汇总一致，且 UI 不得用明细行自行求和 |

## 7. 重点风险与建议

### R1：当前动销分子不是当前铺店集合的子集（高）

当前分子条件只要求近 7 天净销量 `> 0`，当前分母只要求实时库存 `> 0`。售罄商品会进入分子但不进入分母，因此总计动销率可能超过 100%；当分母为 0、分子大于 0 时，SQL 又直接返回 0，造成“动销数大于 0、动销率等于 0”的组合。

若产品定义是“当前仍有库存商品中的近 7 天动销率”，分子应同时限制当前库存 `> 0`。若产品定义允许售罄商品进入分子，则不宜使用当前铺店数作为分母。

### R2：期间铺店不是“期间曾铺货”（高）

期间铺店只看期末库存近似值 `> 0` 或普通销售净量 `> 0`。期间曾入库、之后全部调出且没有销售的对象不会被计入。应由产品确认“铺店”究竟表示期末仍在店/期间售出过，还是期间任意时刻曾有库存。

### R3：赠品进入总销量但不进入期间动销（中高）

`qj_total_sale_num` 包含普通销售、积分赠品、储值卡赠品；但期间 SKC/SPU 动销只使用 `sumSale_num_qj`。如果赠品也应代表商品发生动销，需要改用统一的销量口径。

### R4：当前时间是动态的，期间结束日是固定的（中高）

原 SQL 隔日重跑时，当前库存、在店天数和近 7 天销售都会变化，而期间仍固定为 `2026-08-01` 至 `2026-09-21`。验收、回归和历史复盘应把“当前基准时间”参数化或保存快照。

### R5：近 7 天混用 Date 与 DateTime（中）

预过滤使用 `bill_date >= addDays(today(), -7)`，实际求和使用 `bill_date >= now() - INTERVAL 7 DAY`。若 `bill_date` 是 Date，边界日会以零点与当前时刻比较，通常形成“今天 + 前 6 个完整自然日”，但表达方式容易引起 7/8 天歧义。建议明确采用自然日口径并统一成 Date 比较。

### R6：明细行不可直接累加 SKC/SPU 指标（中）

最外层按 SKU 展示字段分组。同一 SKC/SPU 会出现在多个 SKU 行中，每行的 SKC/SPU 指标可能都是 1。页面或导出若对明细行求和，会重复计数；总指标应读取 `WITH TOTALS` 行或单独按 SKC/SPU 去重计算。

### R7：库存出库符号必须确认（中）

期间期末库存公式为 `期初 + 入库 + 出库`。只有当 `out_num` 在源表中为负数时才符合通常的库存平衡式；若源表把出库存为正数，公式应为 `期初 + 入库 - 出库`。

## 8. 验收判定

1. 第 X 周所有边界案例只进入一个桶，且有效生命周期销售满足周销量守恒。
2. 12 个字段与本文件映射一致；SKU、SKC、SPU 层级没有混用。
3. 若业务要求标准百分比，SKC/SPU 当前和期间动销率均处于 `[0,1]`。
4. 期间动销数不得大于期间铺店数；当前指标若保留现有口径，需要对例外给出明确产品解释。
5. 任何同一门店 + SKU 的中间结果在窗口汇总前只保留一行，避免 JOIN 放大。
6. 总计行与不带 `LIMIT` 的独立聚合结果一致，前端不得累加 SKU 明细行得到 SKC/SPU 总数。
7. 产品需书面确认三项口径：售罄商品是否算当前动销、赠品是否算期间动销、期间铺店是否包含曾铺货但期末为零且未销售的商品。
