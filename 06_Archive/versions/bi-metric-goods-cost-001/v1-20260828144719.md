# 商品成本计算

## 一句话结论

销售成本需区分标准成本和总部综合成本，并按 SKU/SPU 兜底规则、门店分摊比例及 CASE 优先级确定成本单价。

## 记忆内容

### 问题 / 场景

核对销售成本、毛利和成本单价来源时使用。

### 核心结论

标准成本优先取 SKU 成本价后兜底 SPU 成本价；总部综合成本由销售数量、综合成本价和门店费用分摊比例共同决定。

### 使用方法

分别构造 SKU 成本为正数、0、NULL 和 SPU 有/无值的测试数据；针对总部综合成本逐一验证 `storage_id` 条件和已确认的 CASE 分支优先级。

## 一、标准成本

来源表：`flowload.dim_goods_sku_bi`

标准成本金额：

```text
标准成本 = sum(sale_total_stand_cost_money_new)
标准成本金额 = sale_total_num * stand_cost_price
```

标准成本单价优先级：

```text
SKU 成本价 sku_cost_price
  -> SKU 成本价为空或 0
SPU 成本价 spu_cost_price
```

因此不能只判断字段是否为 NULL，还必须把 0 视为空成本处理。

## 二、总部综合成本

来源表：`flowload.dim_goods_composite_cost_price_bi_ds`

门店属性关联表：`flowload.dim_corp_storage_bi`

```text
总部综合成本 = sum(sale_total_zh_cost_money_new)
all_sale_zhcb_money = sale_total_num * basis_composite_cost_price
```

`sale_total_zh_cost_money_new` 规则：

```sql
if(
    storage_id is null or storage_id = 0,
    sumAll_sale_zhcb_money,
    cost_type_zb * sumAll_sale_zhcb_money
)
```

综合成本价候选字段包括：

1. `zb_last_purchase_in_price`：总部最近采购价
2. `zb_real_cost_price`：总部实际成本价
3. `spu_standard_cost_price * 1.02`
4. `sku_price3 * 0.76`
5. `sku_standard_purchase_price * 1.21`
6. `zongbu_cost_price`：总部成本价
7. `zongbu_per_month_cost_price`：总部月成本价
8. `zb_month_cost_price`：总部月结成本价

部分成本字段的 SKU/SPU 兜底规则：

```text
SKU 有值 -> 取 SKU
SKU 无值且 SPU 有值 -> 取 SPU
都没有 -> NULL
```

`basis_composite_cost_price` 还存在按 CASE 顺序处理的特殊分支，包括总部商品、特定仓库类型、特定门店/区域/渠道组合和特殊 `storage_id`。CASE 的先后顺序会影响最终成本价，测试时必须逐分支构造数据验证。

## 测试关注点

- SKU 成本价为 NULL、0、正数时分别验证。
- SPU 兜底和最终 NULL 的处理。
- `storage_id` 为 NULL、0、有效门店时验证 `cost_type_zb` 是否生效。
- 各 CASE 分支同时命中时验证优先级。
- 金额乘法、倍率和小数精度验证。
