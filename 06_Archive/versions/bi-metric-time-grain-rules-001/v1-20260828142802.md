# 报表同环比时间维度与粒度规则

## 一句话结论

先判断列表是否自带时间字段，再确定同环比粒度；时间标识必须包含年份，组合维度取最细的有效粒度，不能把明细唯一键当作跨期匹配键。

## 1. 同环比粒度判定

### 列表没有时间维度

同环比粒度由筛选控件决定：

- 日筛选按日计算。
- 周筛选按周计算。
- 月筛选按月计算。
- 季筛选按季度计算。
- 年筛选按年计算。
- 自定义日期按自定义日期范围计算。

### 列表已有时间维度

同环比粒度由列表字段决定，筛选控件只负责限制数据范围：

| 列表字段 | 计算粒度 |
| --- | --- |
| 日期 | 日 |
| 年份 | 年 |
| 年季 | 季 |
| 年月 | 月 |
| 年周 / `yearWeek` | 周 |

例如列表包含 `yearWeek` 时，即使筛选器选择自定义日期，仍按周进行同环比。

## 2. 可用与高风险时间字段

推荐使用带年份的标准值：

- 日期：`2026-08-28`
- 年份：`2026`
- 年季：`2026S01`
- 年月：`2026-01`
- 年周：`2026W01`

不建议单独使用只有月份、只有周次或不带年份的周日期范围，例如 `01`、`31`、`20260817~20260819`。这些值跨年后无法唯一匹配，容易把不同年份的记录混在一起。

## 3. 多时间维度组合

最终同环比粒度取最细的有效时间维度：

- `年份 + 年月`：按月。
- `年份 + 年季 + 年月`：仍按月。
- 任意时间维度 + `日期`：按日。

为避免重复或口径冲突，建议：

- 周分析尽量只使用年周。
- 月分析尽量只使用年月。
- 日分析使用日期。
- 不要同时混用月份、周次、周内日期等互相包含的粒度。

一个周可能跨越两个自然月，例如 `2026-03-30` 至 `2026-04-05`。同时按月和周分组会拆分同一周，导致同比或环比重复、无法匹配或口径不一致。

## 4. 同比、环比公式

```text
环比 = (本期值 - 上期值) / abs(上期值)
同比 = (本期值 - 同期值) / abs(同期值)
```

对比基准为空或为 0 时返回 `NULL`，不要强行显示为 0% 或 100%。

周维度应遵循 ISO 周规则：周一是一周开始，周四所在年份决定 ISO 周年；跨年周不能只按自然年份判断。本期是部分周时，上期和同期也必须使用相同的星期范围。

## 5. 明细字段与 SQL 注意事项

订单 ID、唯一流水号、明细 ID 等明细唯一字段通常无法跨期间匹配，不适合直接作为同比维度。应使用店仓、品牌、商品与周次等稳定业务维度，例如：

```text
店仓 + 周次
品牌 + 店仓 + 周次
商品 + 周次
```

使用 `periodStart` 和 `addDays(periodStart, -7)` 计算周环比时，必须同步维护本期、上期、同期日期以及 `yearWeek` 条件，不能只修改周标签。日期边界、跨年周和部分周要保持同一口径。

## 6. 复用检查清单

- 列表是否已经包含时间字段？
- 当前使用的是日期、年月还是 ISO 年周？
- 时间值是否携带年份？
- 是否混用了父子时间粒度？
- 本期、上期、同期是否使用相同的日期范围？
- 对比键是否是可跨期匹配的业务维度，而不是明细 ID？
- 基准为空或为 0 时是否返回 `NULL`？
