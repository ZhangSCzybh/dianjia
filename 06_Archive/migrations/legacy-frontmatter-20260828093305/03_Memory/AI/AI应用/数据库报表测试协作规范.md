## 记忆内容

### 问题 / 场景

需要借助 AI 分析数据表、校验 BI SQL、追踪报表差异或生成测试基准时使用。

### 核心结论

AI 可执行技术核验，但业务正确性依赖指标定义；数据库凭据和查询范围必须最小化、只读化和脱敏化。

### 使用方法

按“指标定义 → 表和字段定位 → 基准 SQL → 报表 SQL 复现 → 订单级差异下钻 → 测试结论”执行，并在每一步保留可复用结果。

## 推荐工作流

1. 先提供报表名称、筛选条件、指标定义和预期周期。
2. AI 只读定位数据库、表、字段和日期范围。
3. 先生成源表基准查询，再复现报表 SQL。
4. 按订单/明细下钻差异，定位 Join、过滤或口径问题。
5. 输出期望值、实际值、差异原因和修正建议。

## 安全要求

- 使用只读账号。
- 密码只从本地环境变量或密钥管理读取，不写入 SQL、代码、总结或截图。
- 连接探测只执行 `SELECT 1` 或元数据查询。
- 结果中不输出客户手机号等敏感明细，订单级核对应尽量脱敏。
- 不执行写入、删除、DDL 或无必要的大范围扫描。

## 判断原则

SQL 能执行只代表语法正确；必须结合指标口径、数据粒度、会员定义、退款规则和时间周期判断业务正确性。
