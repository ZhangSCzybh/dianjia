# 会员分类与单效指标

## 适用场景

店家销售 BI 报表中拆分会员/非会员销售金额和单效单数。

## 核心计算

```sql
source_sale_money = sale_deal_money - sale_refund_money
```

会员销售金额：

```sql
if(basis_bool_membership = 1, sumBasis_sale_single_effect_money, 0)
```

非会员销售金额：

```sql
if(basis_bool_membership = 0, sumBasis_sale_single_effect_money, 0)
```

单效单数不是简单的 `count(distinct id)`。有效成交订单需要满足金额不为 0，并根据 `statistic_type`、退款状态、虚拟商品和剔除商品规则生成 `sell_order_num`。

## 会员判断风险

以下写法含义不同：

```sql
custom_id > 0
```

表示订单带有客户编号；

```sql
cus_mobile_phone is not null and cus_mobile_phone != ''
```

表示关联到的会员资料手机号有效；

```sql
where brand_id = ? and storage_id = ?
```

表示只在某店铺范围内找会员资料。

如果业务定义是品牌会员，会员维表应至少按品牌和有效状态关联：

```sql
SELECT custom_id, cus_mobile_phone
FROM flowload.view_dim_customer_info_bi_bl_store FINAL
WHERE brand_id = 15056
  AND deleted = 0
```

不应无依据地加当前销售店铺的 `storage_id` 限制。

## 常用基准查询

```sql
SELECT
    if(custom_id > 0, '会员', '非会员') AS member_type,
    round(sum(sale_deal_money - sale_refund_money), 2) AS effect_amount
FROM flowload.dm_order_item_sale_bi_ds FINAL
WHERE brand_id = 15056
  AND storage_id = 1217909137551395841
  AND bill_date >= '2026-08-15'
  AND bill_date < '2026-08-22'
GROUP BY member_type;
```

这条查询只适用于“`custom_id > 0` 即会员”的口径。若报表按会员维表判断，必须复现其 Join 和手机号规则后再对账。
